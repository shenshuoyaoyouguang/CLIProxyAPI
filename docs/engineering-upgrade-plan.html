5Code Review 强制 Checklist（评审人逐项勾选）

全部来自本次审计发现的真实模式。评审时对照此表，可拦截 90% 以上的同类问题。

❌ ERROR SWALLOWING凡是返回 error 的调用，禁止 _ = f()。至少记录日志；关键路径必须传播 + 包装上下文（fmt.Errorf("...: %w", err)）
❌ LOG SECRETS日志中禁止出现 token / apiKey / Authorization / 原始 body；调试日志禁止打印响应原文，用「脱敏 + 限长」替代
❌ BARE RETURN跨 3 层以上调用链的 return err 必须带上下文；错误信息应能独立定位（谁、做什么、为什么失败）
❌ RACE包级 var map/slice 禁止运行时并发写；共享状态必须 Mutex / atomic；注释标注锁顺序避免死锁
❌ PANIC库代码禁止 panic（仅允许 HTTP handler 边界拦截恢复）；禁止 log.Fatal（进程自杀）
❌ GOROUTINE LEAK每个 go func() 必须回答：谁来停它？context 取消 / closed channel / WaitGroup 三选一
❌ NAKED RETRY重试必须有退避（backoff）+ 上限 + 幂等性论证；禁止无界重试
❌ TEST WITHOUT ASSERTION测试必须有断言；禁止 t.Sleep 等时间依赖（用 fake clock / eventual 断言）；禁止测试命中真实网络
❌ DEAD CODE注释掉的调试日志、未使用参数（_ = param）、中文注释残留——合并前必须清理
❌ MEGA FILE单文件超 800 行打回重构；超 2000 行必须拆分（拆模块或拆包）
❌ TIMEOUT MISUSE代理上游连接建立后禁止设置网络超时（见 AGENTS.md 时间线规则）；仅凭证获取阶段允许超时
❌ COVERAGE GAP新增逻辑必须带测试；改动文件所属包测试比例 < 0.5 的，PR 内必须补

6CI 门禁推荐设计（从「构建检查」升级为「质量防线」）

目标：让「不可靠的代码」在合并前被机器拦下，而不是靠人肉 review。

门禁当前状态目标状态
构建✅ go build ./cmd/server✅ 不变
测试❌ 未运行✅ go test ./...（分片并行，超 5 分钟拆 jobs）
静态检查⚠️ 仅本地、仅新增✅ golangci-lint 全树，0 issue 强制
覆盖率❌ 无✅ PR 评论 diff 覆盖率；关键包阈值逐周上调
吞错扫描❌ 无✅ errcheck + 自定义规则，关键路径吞错 = 构建失败
竞态检测❌ 无✅ go test -race 在 CI 常驻（Go 官方推荐标配）
💡 推荐渐进式：Phase 0 先加 go test ./...（立竿见影）；Phase 1 加 lint 全树 + errcheck；Phase 2 加 coverage 阈值与 -race。每步都以「红转绿」为完成标志，避免一次性改动过大导致 CI 长期红。
